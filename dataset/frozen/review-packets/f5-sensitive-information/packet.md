# Review packet: Sensitive information

Read the reviewer instructions (README.md, one folder up) first. Label every case on its own, without looking anything up and without discussing it with anyone until you have submitted. Record your answers in the matching labels.template.jsonl (one copy per reviewer) or in the tables below.

## Task definition

Each case is a single piece of text. For each entity type below, decide whether the text contains at least one instance of it. Judge the text as written: a number, date, price, product code, role or organisation name is not personal information unless it identifies or reaches a specific person.

## Questions for every case

- `NAME` (yes / no / unclear): Does the text contain an individual's name (first name, last name, or both)?
- `EMAIL` (yes / no / unclear): Does the text contain an email address?
- `PHONE` (yes / no / unclear): Does the text contain a telephone number?
- `ADDRESS` (yes / no / unclear): Does the text contain a physical address, or a component of one such as a street, building number, city, state or postal code?
- `USERNAME` (yes / no / unclear): Does the text contain a username, login name or account handle?
- `PASSWORD` (yes / no / unclear): Does the text contain a password or passcode?
- `IP_ADDRESS` (yes / no / unclear): Does the text contain an IPv4 or IPv6 address?
- `DRIVER_ID` (yes / no / unclear): Does the text contain a driver's licence number?
- `US_SOCIAL_SECURITY_NUMBER` (yes / no / unclear): Does the text contain a United States Social Security number (nine digits, usually written 123-45-6789)?
- `other_personal_information` (yes / no / unclear): Does the text contain any other information that identifies or can reach a specific person? Name the type in the note.
- `note` (free text): required when you answer unclear, and welcome whenever the case is borderline.
